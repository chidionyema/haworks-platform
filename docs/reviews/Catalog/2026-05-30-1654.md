## CRITICAL: Security Vulnerability - User ID Header Spoofing

### CRITICAL: Missing Authorization Validation in User ID Forwarding
- **File**: src/Catalog/Catalog.Api/Controllers/ProductReviewsController.cs:32
- **Issue**: Controllers use `HttpContext.GetForwardedUserId()` without validating the forwarded user ID header against the authenticated principal
- **Impact**: Attackers could spoof X-User-Id header to impersonate other users and create/modify reviews as any user
- **Fix**: Validate that the forwarded user ID matches the authenticated principal's claims:
```csharp
var userId = HttpContext.GetForwardedUserId();
var claimUserId = User.FindFirstValue(ClaimTypes.NameIdentifier);
if (!string.Equals(userId, claimUserId, StringComparison.Ordinal))
{
    return Unauthorized("User ID mismatch");
}
```

### CRITICAL: Hardcoded Currency Bypass Business Logic
- **File**: src/Catalog/Catalog.Api/Controllers/ProductsController.cs:67
- **Issue**: Currency is hardcoded to "USD" instead of using request currency, bypassing multi-currency support
- **Impact**: All products will be created in USD regardless of business requirements, breaking international commerce
- **Fix**: Use the currency from request: `Money.FromMajorUnits(body.UnitPrice, body.Currency ?? "USD").MinorUnits`

## HIGH: Domain Logic Correctness Issues

### HIGH: Incorrect Stock State Logic
- **File**: src/Catalog/Catalog.Domain/Product.cs:102
- **Issue**: `ReleaseStock()` always sets `IsInStock = true`, even when releasing stock to a product that had zero quantity
- **Impact**: Products with 0 stock will incorrectly show as "in stock" after any stock release
- **Fix**: 
```csharp
public void ReleaseStock(int quantity)
{
    if (quantity <= 0) throw new ArgumentException("Quantity must be positive", nameof(quantity));
    StockQuantity += quantity;
    IsInStock = StockQuantity > 0; // Fix: only true if quantity > 0
    LastModifiedDate = DateTime.UtcNow;
}
```
