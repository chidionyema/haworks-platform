## CRITICAL: Race Condition in Multipart Upload Completion

### CRITICAL: Concurrent multipart completion vulnerability
- **File**: src/Media/Media.Api/Application/CompleteMultipartUpload.cs:47-120
- **Issue**: Two concurrent requests can both attempt to complete the same multipart upload, leading to duplicate processing, file corruption, or inconsistent state. No pessimistic locking prevents this.
- **Impact**: Data corruption, duplicate virus scans, inconsistent database state, potential security bypass if one scan passes and another fails
- **Fix**: Add pessimistic row locking before state changes:
```csharp
var mediaFile = await context.MediaFiles
    .FromSql($"SELECT * FROM media.\"MediaFiles\" WHERE \"Id\" = {request.MediaId} FOR UPDATE")
    .FirstOrDefaultAsync(ct);
```

- **File**: src/Media/Media.Api/Application/CompleteMultipartUpload.cs:71-75
- **Issue**: Downloads entire file to temp storage without disk space checks or file size limits. A 256GB file will consume 256GB of disk space during scanning.
