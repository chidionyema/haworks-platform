## ## CRITICAL: Race Condition in Table Initialization

### CRITICAL: Race condition in EnsureTableAsync
- **File**: src/Orders/Orders.Api/Controllers/DemoIdempotencyController.cs:206-222
- **Issue**: The `Volatile.Write(ref s_tableInitialized, 1)` executes immediately after the SQL command without verifying success. If the `CREATE TABLE` fails, the flag is still set to 1, causing all subsequent calls to skip table creation entirely.
- **Impact**: Complete failure of demo functionality after any SQL error, with no recovery path
- **Fix**: Move the Volatile.Write inside a try-catch and only set it after successful execution:
```csharp
try {
    await db.Database.ExecuteSqlRawAsync(/*...*/);
    Volatile.Write(ref s_tableInitialized, 1);
} catch {
    // Don't set the flag on failure
    throw;
}
```

### HIGH: Integer overflow in line total calculation
- **File**: src/Orders/Orders.Domain/OrderItem.cs:33
- **Issue**: `LineTotalCents => Quantity * UnitPriceCents` can overflow with large quantities or expensive items. No bounds checking on input values.
- **Impact**: Silent arithmetic overflow leading to incorrect order totals, potential financial loss
- **Fix**: Add overflow checking in OrderItem.Create():
```csharp
if (quantity > 0 && unitPriceCents > long.MaxValue / quantity)
    throw new ArgumentException("Line total would overflow");
```
