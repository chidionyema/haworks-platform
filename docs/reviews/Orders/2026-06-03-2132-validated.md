# Comprehensive Code Review: Orders Service

## HIGH: Integer overflow in line total calculation
- **File**: src/Orders/Orders.Domain/OrderItem.cs:33
- **Issue**: `LineTotalCents => Quantity * UnitPriceCents` can overflow with large quantities or expensive items. No bounds checking on input values.
- **Impact**: Silent arithmetic overflow leading to incorrect order totals, potential financial loss
- **Confidence**: 8
- **Fix**: Add overflow checking in OrderItem.Create():
```csharp
if (quantity > 0 && unitPriceCents > long.MaxValue / quantity)
    throw new ArgumentException("Line total would overflow");
```

- **Impact**: Potential DoS attacks through table creation/manipulation if deployed to production
- **Confidence**: 10
- **Fix**: Restrict to development environment only or add proper authorization

## MEDIUM: Missing bounds validation
- **File**: src/Orders/Orders.Application/Validators/CreateOrderCommandValidator.cs:13-24
- **Issue**: Only validates that amounts/quantities are positive, no upper bounds checking
- **Impact**: Could allow creation of orders with unrealistic values (e.g., quantity = int.MaxValue)
- **Confidence**: 8
- **Fix**: Add reasonable upper bounds:
```csharp
RuleFor(x => x.TotalAmountCents).GreaterThan(0).LessThan(1_000_000_00L); // $10M limit
RuleForEach(x => x.Items).ChildRules(item => {
    item.RuleFor(i => i.Quantity).GreaterThan(0).LessThan(10_000); // Reasonable quantity limit
});
```
