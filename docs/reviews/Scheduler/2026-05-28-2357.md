# Scheduler Service Code Review

## CRITICAL FINDINGS

### CRITICAL: Missing Database Tables and DbSets
- **File**: src/Scheduler/Scheduler.Infrastructure/Persistence/SchedulerDbContext.cs:19-23
- **Issue**: `VaultLease` and `RotationAuditEntry` entities are configured in `OnModelCreating` but missing corresponding `DbSet<>` properties
- **Impact**: Runtime exceptions when jobs try to query these tables; EF cannot generate proper SQL
- **Fix**: Add missing DbSets:
```csharp
public DbSet<VaultLease> VaultLeases => Set<VaultLease>();
public DbSet<RotationAuditEntry> RotationAuditEntries => Set<RotationAuditEntry>();
```

### CRITICAL: Missing Migration for Core Tables  
- **File**: src/Scheduler/Scheduler.Infrastructure/Migrations/20260513080006_InitialCreate.cs
- **Issue**: Migration only creates MassTransit outbox/inbox tables, completely missing `VaultLeases` and `RotationAuditEntries` tables
- **Impact**: Application will crash on startup when trying to access non-existent tables
- **Fix**: Generate new migration with `dotnet ef migrations add AddVaultLeasesTables`

### CRITICAL: Missing Dependency Registration
- **File**: src/Scheduler/Scheduler.Infrastructure/DependencyInjection.cs:20-50
- **Issue**: `VaultSharp.IVaultClient` is not registered in DI container but required by all rotation jobs
- **Impact**: Startup will fail with "Unable to resolve service" exceptions (confirmed in migration drift output)

```csharp
services.AddVaultSharp(configuration);
// or configure VaultSharp client properly
```

## HIGH SEVERITY FINDINGS

### HIGH: Outbox Pattern Violation in Event Publishing
- **File**: src/Scheduler/Scheduler.Application/Jobs/LeaseWatcherJob.cs:115-119, 142-147, 169-174
- **Issue**: Publishing MassTransit events BEFORE `SaveChangesAsync()` calls in rotation logic
- **Impact**: Events could be published even if database transaction fails, leading to phantom events
- **Fix**: Move all `_publishEndpoint.Publish()` calls AFTER `SaveChangesAsync()` calls

### HIGH: Race Condition in Lease Rotation
- **File**: src/Scheduler/Scheduler.Application/Jobs/LeaseWatcherJob.cs:86-93
- **Issue**: Lease marked as "Rotating" and saved, but if rotation fails, lease stays stuck in Rotating state
- **Impact**: Leases could get permanently stuck, blocking future rotations
- **Fix**: Wrap entire rotation in try-catch and reset status on any failure

### HIGH: Fragile Exception Type Checking
- **File**: src/Scheduler/Scheduler.Application/Jobs/LeaseWatcherJob.cs:94-99
- **Issue**: Using string comparison `ex.GetType().Name == "DbUpdateConcurrencyException"` instead of type checking
- **Impact**: Will miss actual concurrency exceptions if type name changes; brittle code
- **Fix**: Use proper exception handling:
```csharp
catch (DbUpdateConcurrencyException ex)
```

### HIGH: Hangfire Dashboard Authorization Bug
- **File**: src/Scheduler/Scheduler.Api/Program.cs:80-91
- **Issue**: Authorization filter requires BOTH `isLocal` AND `User.IsInRole("admin")` - local requests won't have admin role
- **Impact**: Dashboard completely inaccessible in development
- **Fix**: Change logic to `return isLocal || httpContext.User.IsInRole("admin");`

### HIGH: Missing Transaction Boundaries in Bootstrap
- **File**: src/Scheduler/Scheduler.Api/Infrastructure/LeaseBootstrapStartupTask.cs:45-60
- **Issue**: Adding multiple leases but only one `SaveChangesAsync()` call at the end without transaction
- **Impact**: Partial failures could leave system in inconsistent state
- **Fix**: Wrap entire operation in explicit transaction
