## CRITICAL: SSRF via DNS-rebinding bypass in webhook URL validation — CONFIRMED (confidence 9/10)
- **File**: `src/Webhooks/Webhooks.Application/Subscriptions/SubscriptionValidators.cs:30,45,101` + `src/Webhooks/Webhooks.Application/Subscriptions/SubscriptionHandlers.cs:96-110`
- **Verified**: `SubscriptionValidators.cs:47` — `IsPrivateIp` opens with `if (!System.Net.IPAddress.TryParse(host, out var ip)) return false;`, so any non-literal hostname short-circuits to "not private" without ever resolving DNS. `SubscriptionHandlers.cs:100-102` then does `httpFactory.CreateClient("WebhookValidator")` → `client.PostAsJsonAsync(url, ...)`, a real outbound POST from the Webhooks service. `DependencyInjection.cs:44-47` confirms `AllowAutoRedirect = false` is the only other mitigation — irrelevant to DNS rebinding.
- **Impact**: As stated — any authenticated caller (no role restriction, see finding below) can register `https://attacker-controlled.example` pointed at an internal Fly `*.internal` host or `169.254.169.254`, triggering a real request from platform infrastructure.
- **Fix**: Resolve the hostname via `Dns.GetHostAddressesAsync` before validating, run `IsPrivateIp` against every resolved address, and pin the `HttpClientHandler.ConnectCallback` to the pre-validated IP so a second lookup at connect time can't rebind. Reject if any resolved address is private/link-local/loopback/multicast.

### HIGH: Webhook secret is never returned to the caller — feature is unusable as built — CONFIRMED (confidence 9/10)

Guid.NewGuid().ToString("N");`, is server-generated when omitted; line 47 returns only `Result.Success(sub.Id)` — the generated secret is discarded.
