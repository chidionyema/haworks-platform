# Exhaustive Code Review: Payments Microservice

## ## CRITICAL: Idempotency Keys Generated Fresh on Every Request

### CRITICAL: Broken Idempotency in API Controllers
- **File**: src/Payments/Payments.Api/Controllers/Admin/StripeKeyRotationController.cs:33
- **Issue**: `Guid.NewGuid().ToString("N")` generates a new GUID on every request, defeating idempotency
- **Impact**: API retries will be treated as separate operations, potentially causing duplicate key rotations
- **Fix**: Accept idempotency key from client or derive deterministically from request content

### CRITICAL: Broken Idempotency in Refunds Controller  
- **File**: src/Payments/Payments.Api/Controllers/RefundsController.cs:23
- **Issue**: `Guid.NewGuid().ToString("N")` generates fresh GUID per request
- **Impact**: Duplicate refund requests on network timeouts will create multiple refunds
- **Fix**: 
```csharp
var command = new CreateRefundCommand(
    body.PaymentId,
    body.AmountCents, 
    body.Currency,
    body.IdempotencyKey ?? GenerateDeterministicKey(body.PaymentId, body.AmountCents),
    body.Reason,
    body.RequestedBy);
```

### CRITICAL: Broken Idempotency in Subscriptions
- **File**: src/Payments/Payments.Api/Controllers/SubscriptionsController.cs:39,58,75
- **Issue**: Multiple instances of `Guid.NewGuid().ToString("N")` 
- **Impact**: Subscription operations not idempotent, could create duplicate subscriptions
- **Fix**: Accept client-provided idempotency keys or derive from user+operation context
