- **File**: src/Search/Search.Application/Consumers/CategoryUpdatedConsumer.cs:31-49
- **Issue**: While loop with `page++` but no upper bound protection. If SearchAsync consistently returns BatchSize results due to index corruption or concurrent writes, this creates an infinite loop.
- **Impact**: Consumer thread hangs indefinitely, blocking message processing for the entire queue
- **Fix**: Add maximum page limit protection:
```csharp

const int MaxPages = 1000;
while (page <= MaxPages)
{

    if (hits.Hits.Count == 0) break;
    // ... process hits ...
    if (hits.Hits.Count < BatchSize) break;

}
```

## HIGH Severity Issues

### HIGH: Elasticsearch Bulk Operation Ignores Item-Level Failures (confidence: 9/10)
- **File**: src/Search/Search.Infrastructure/Elasticsearch/ElasticsearchIndex.cs:82-86
- **Issue**: Only checks `response.IsSuccess()` but doesn't validate individual bulk operation items. Elasticsearch bulk can return 200 with partial failures.
- **Impact**: Silent data loss - some documents may fail to index without detection
- **Fix**: Check individual item responses:
```csharp
if (!response.IsSuccess())
{
    _logger.LogError("Elasticsearch bulk upsert failed: {Debug}", response.DebugInformation);
    throw new InvalidOperationException("Search upsert failed");
}
// Add item-level validation
if (response.Items?.Any(item => item.Error != null) == true)
{
    var failures = response.Items.Where(item => item.Error != null);
    throw new InvalidOperationException($"Bulk upsert had item failures: {string.Join(", ", failures.Select(f => f.Error?.Reason))}");
}
```
