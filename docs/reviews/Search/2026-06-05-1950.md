## CRITICAL Issues

### CRITICAL: Potential Infinite Loop in Category Rename
- **File**: src/Search/Search.Application/Consumers/CategoryUpdatedConsumer.cs:30-46
- **Issue**: While loop with `page++` but no upper bound protection. If SearchAsync consistently returns BatchSize results due to index corruption or concurrent writes, this creates an infinite loop.
- **Impact**: Consumer thread hangs indefinitely, blocking message processing for the entire queue
- **Fix**: Add maximum page limit and timeout protection:
```csharp
var page = 1;
const int MaxPages = 1000; // Reasonable upper bound
while (page <= MaxPages)
{
    var hits = await _index.SearchAsync(/* ... */, context.CancellationToken);
    if (hits.Hits.Count == 0) break;
    // ... process hits ...
    if (hits.Hits.Count < BatchSize) break;
    page++;
}
if (page > MaxPages)
    _logger.LogWarning("Category rename exceeded maximum pages for {CategoryId}", msg.CategoryId);
```

### HIGH: Elasticsearch Bulk Operation Ignores Item-Level Failures
- **File**: src/Search/Search.Infrastructure/Elasticsearch/ElasticsearchIndex.cs:145-153
- **Issue**: Only checks `response.IsSuccess()` but doesn't validate individual bulk operation items. Elasticsearch bulk can return 200 with partial failures.
- **Impact**: Silent data loss - some documents may fail to index without detection
- **Fix**: Check individual item responses:
```csharp
if (!response.IsSuccess() || response.Items.Any(item => item.Error != null))
{
    var failures = response.Items.Where(item => item.Error != null).ToList();
    _logger.LogError("Elasticsearch bulk upsert had {FailureCount} failures: {@Failures}", 
        failures.Count, failures.Select(f => new { f.Id, f.Error.Reason }));
    throw new InvalidOperationException($"Search upsert failed with {failures.Count} item failures");
}
```
