## CRITICAL: EasyPost webhook has no signature verification — fully spoofable
- **Confidence: 10/10**
- **File**: `src/Shipping/Shipping.Api/Controllers/ShipmentsController.cs:93-133` (`HandleWebhook`, `[AllowAnonymous]` at line 94)

## HIGH: BuyLabel violates the Three-Phase Gateway law — double-purchase race
- **Confidence: 9/10**
- **File**: `ShipmentsController.cs:45-68` (`BuyLabel`); `Shipment.cs:56-68` (`MarkLabelPurchased`)
- **Issue**: Confirmed. No pessimistic lock or "Pending" phase before `provider.BuyLabelAsync` (line 50, external call); `MarkLabelPurchased` unconditionally sets fields with no `Status` guard (lines 56-68 — no check that `Status != LabelPurchased`).
- **Impact**: As stated — two concurrent/retried `/buy` calls both hit EasyPost's `Buy()` before either commits.
- **Fix**: Per CLAUDE.md Law #2 — Phase 1: `FOR UPDATE` lock the row, set `Status = Pending`, commit. Phase 2: call EasyPost (no DB lock held). Phase 3: re-lock, `if (shipment.Status != Pending) return Conflict();` then finalize.
