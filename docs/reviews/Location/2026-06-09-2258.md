## CRITICAL: Database Transaction & Event Consistency

### CRITICAL: Event Publishing Before Transaction Commit
- **File**: src/Location/Location.Application/Commands/CreateAddressCommand.cs:68-78
- **Issue**: Event is published before `SaveChangesAsync()`, creating potential inconsistency
- **Impact**: If `SaveChanges` fails after event publishing, the event remains in outbox but address creation failed, leading to phantom location events
- **Fix**: Move the publish call after `SaveChangesAsync()` or use a transaction scope to ensure atomicity

```csharp
// Current (problematic):
await publisher.Publish(new LocationUpdated { ... }, cancellationToken);
await dbContext.SaveChangesAsync(cancellationToken);

// Fix:
await dbContext.SaveChangesAsync(cancellationToken);
await publisher.Publish(new LocationUpdated { ... }, cancellationToken);
```
