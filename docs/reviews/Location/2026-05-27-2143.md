## CRITICAL: Invalid Coordinate Fallback Creates Bad Data

### CRITICAL: Geocoding failure results in invalid (0,0) coordinates
- **File**: src/Location/Location.Application/Commands/CreateAddressCommand.cs:39-40
- **Issue**: When both latitude/longitude are null, the code sets `lat = 0` and `lon = 0`, then attempts geocoding. If geocoding fails, the address gets created with coordinates (0,0) - a point in the Atlantic Ocean off Africa's coast.
- **Impact**: Creates fundamentally invalid address records that will break distance calculations and geospatial queries. Users searching for nearby addresses will get nonsensical results.
- **Fix**: 
```csharp
if (coords == null)
{
    return Result.Failure<Guid>(Error.Validation("Address.GeocodingRequired", 
        "Address coordinates are required and could not be determined through geocoding"));
}
```

### CRITICAL: IDOR vulnerability in gRPC hydration service  
- **File**: src/Location/Location.Api/Services/LocationHydrationService.cs:26-36
- **Issue**: The service accepts up to 1000 location IDs and returns address details for all valid IDs, but doesn't verify the authenticated user has permission to access those specific addresses.
- **Impact**: User A could request address details for addresses created by User B, potentially exposing sensitive location data across tenant boundaries.
- **Fix**: Add authorization checks:
```csharp
var userAccessibleIds = await AuthorizeLocationAccess(guids, context.GetHttpContext().User);
var addresses = await dbContext.Addresses
    .AsNoTracking()
    .Where(a => userAccessibleIds.Contains(a.Id))
    .ToListAsync(context.CancellationToken);
```

### HIGH: Spatial distance calculation uses planar geometry instead of geodetic
- **File**: src/Location/Location.Application/QueryHandlers/GetNearbyAddressesQueryHandler.cs:30
- **Issue**: `a.Coordinates.Distance(point)` calculates planar distance on projected coordinates, not accurate geodetic distance for geographic coordinates.
- **Impact**: Distance calculations will be increasingly inaccurate as the search area moves away from the equator and for larger radius searches, leading to incorrect "nearby" results.
- **Fix**: Use PostGIS geodetic functions:
```csharp
.Select(a => new { Address = a, Distance = a.Coordinates.STDistance(point) })
```

### HIGH: Duplicate address constraint will poison EF context
- **File**: src/Location/Location.Infrastructure/Persistence/LocationDbContext.cs:69-71
- **Issue**: The unique constraint `IX_Addresses_Unique_Address` will throw `DbUpdateException` on duplicate addresses, but this isn't handled in the command handler.
- **Impact**: In EF Core, `DbUpdateException` poisons the `DbContext`, breaking the MassTransit outbox pattern and requiring context disposal.
- **Fix**: Use pessimistic locking in the command handler:

    .FirstOrDefaultAsync(cancellationToken);

    return Result.Success(existing.Id); // Idempotent response

```

}
```
