## CRITICAL: Promotion Redemption Result Ignored

### CRITICAL: Business Logic Corruption in Promotion Redemption
- **File**: src/Pricing/Pricing.Application/Consumers/PricingRequestedConsumer.cs:50-57
- **Issue**: The consumer calls `RedeemPromotionCodeCommand` but ignores the result. Even if redemption fails (e.g., code exhausted), it still publishes `PriceCalculatedEvent` with the discounted price.
- **Impact**: Allows unlimited use of exhausted promotion codes. Customers get discounted prices without the promotion code being decremented, leading to financial losses.
- **Fix**: Check the redemption result and publish `PricingFailedEvent` if redemption fails:
```csharp
var redemptionResult = await mediator.Send(new Commands.RedeemPromotionCodeCommand { ... });
if (!redemptionResult.Success)
{
    await context.Publish(new PricingFailedEvent
    {
        SagaId = msg.SagaId,
        OrderId = msg.OrderId,
        Reason = $"Promotion code redemption failed: {redemptionResult.FailureReason}",
    });
    return;
}
```

### HIGH: Race Condition in Per-User Promotion Limits
- **File**: src/Pricing/Pricing.Infrastructure/Repositories/PromotionCodeRepository.cs:92-94
- **Issue**: The per-user redemption count check doesn't use `FOR UPDATE`, allowing race conditions. Two concurrent orders from the same user can both see the same count and exceed the per-user limit.
- **Impact**: Users can exceed per-user promotion limits during concurrent checkouts, violating business rules.
- **Fix**: Use `SELECT ... FOR UPDATE` on the redemption count or move the per-user check before the global limit increment.
