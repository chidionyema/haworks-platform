## CRITICAL: Missing Pessimistic Locking for Concurrency Control
- **File**: All command handlers (ApproveMerchant, UpdateMerchant, SetOperatingHours, etc.)
- **Issue**: According to architectural laws in CLAUDE.md, all entity modifications must use pessimistic locking (`FOR UPDATE`), but command handlers use simple `FirstOrDefaultAsync` without locking
- **Impact**: Race conditions can cause lost updates, data corruption, or inconsistent state transitions in high-concurrency scenarios
- **Fix**: Add pessimistic locking to all command handlers:
```csharp
var merchant = await _context.Database.SqlQueryRaw<MerchantProfile>(
    "SELECT * FROM merchant.\"Merchants\" WHERE \"Id\" = {0} FOR UPDATE", 
    request.MerchantId).FirstOrDefaultAsync(cancellationToken);
```

## CRITICAL: URL Security Vulnerability
- **File**: src/Merchant/Merchant.Application/Merchants/Commands/UpdateMerchant/UpdateMerchantCommandValidator.cs:25
- **Issue**: URL validation only checks `Uri.TryCreate()` but allows dangerous schemes like `javascript:`, `data:`, or `file:`
- **Impact**: XSS attacks, data exfiltration, or malicious code execution when URLs are rendered in frontend
- **Fix**: Restrict to safe schemes:
```csharp

```
