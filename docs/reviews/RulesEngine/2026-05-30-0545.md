## CRITICAL: Dynamic Expression Evaluation Security Vulnerability

### **CRITICAL**: Code injection risk via Dynamic LINQ
- **File**: src/RulesEngine/RulesEngine.Api/Infrastructure/RulesEvaluator.cs:94-124
- **Issue**: Uses Dynamic LINQ (`DynamicExpressionParser.ParseLambda`) to compile and execute user-provided expressions, creating a code injection vector
- **Impact**: Even with `SafeTypeProvider` restrictions, Dynamic LINQ parsing of untrusted input is inherently dangerous and could lead to RCE, DoS, or data exfiltration
- **Fix**: Replace with a safe rule engine like Microsoft Rules Engine, or implement a whitelist-based expression parser that only supports specific operators and functions

- **Issue**: Tests mock `IRulesEvaluator.EvaluateAsync` to return `Result.Success(bool)` but actual method returns `Result<RuleEvaluationResult>`
- **Impact**: Tests won't compile, meaning they provide zero coverage
