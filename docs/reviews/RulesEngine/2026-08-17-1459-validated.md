## CRITICAL: Expression injection — substituted Inputs never re-validated, JSON deserialization breaks literal-quoting
- **File**: src/RulesEngine/RulesEngine.Api/Infrastructure/RulesEvaluator.cs:68,97,181-187; EvaluateRuleQuery.cs:8-10
- **Verified**: `Inputs` is `Dictionary<string, object>` with no custom `JsonConverter` registered anywhere in the project (`rg JsonConverter` in src/RulesEngine, src/BuildingBlocks — no hits), so System.Text.Json binds values as `JsonElement`. `ToLiteral` (lines 181-187) has no `JsonElement` case, falls to `value.ToString()`. `JsonElement.ToString()` for `ValueKind.String` returns `GetString()` (raw, unquoted) and for booleans returns `"True"`/`"False"` — both as described. `ValidateExpression` (line 68) runs only against the stored template, never the post-`TransformExpression` string (line 97).
- **Fix**: Bind `Inputs` through a typed converter (bool/double/string) before `ToLiteral`; re-run `ValidateExpression` against the substituted expression.
- **Confidence**: 9/10
