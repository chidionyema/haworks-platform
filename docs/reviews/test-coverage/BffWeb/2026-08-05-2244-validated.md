### E2E — CRITICAL finding (CONFIRMED exactly as audit stated)
`tests/E2E/CheckoutE2ETests.cs:115` and `tests/E2E/CatalogE2ETests.cs:120` both register:
```csharp
conn.On<string, string>("OnPaymentSessionCreated", (id, url) => tcs.TrySetResult(url));
```
Production sends (`src/BffWeb/BffWeb.Api/SignalR/PaymentSessionCreatedConsumer.cs:33-43`):
```csharp
await hub.Clients.Group(...).SendAsync("CheckoutReady", new { sagaId, orderId, paymentId, checkoutUrl, provider, amount, currency }, ct);
```
Both the event name (`OnPaymentSessionCreated` vs `CheckoutReady`) and payload shape (two positional strings vs one 7-field object) mismatch — the handler can never fire; both tests would hang to their 30s timeout and fail. `SignalRPushTests.cs:63,111,181-182` already uses the correct pattern (`On<CheckoutReadyMessage>("CheckoutReady", ...)`). Gated by `E2EEnvironmentFixture.SkipIfNotEnabled()` (`E2E_ENABLED=1`), so it's not failing the fast CI lane today, but the test logic itself is broken regardless of whether it runs.

By extension (zero test references anywhere in `tests/` for the underlying bridge classes), the audit's related E2E gap claims — saga-failure-path E2E, chaos-demo E2E, vault-rotation E2E, AI-passthrough E2E — are also CONFIRMED.
