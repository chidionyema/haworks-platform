## Test Optimization Violations

#### CRITICAL: Fake test — asserts on a literal, never exercises production code
- **File**: `tests/BffWeb/BffWeb.Unit/Demo/ChaosManagerTests.cs:12-20`
- **Violation**: `Snapshot_returns_default_state_when_no_chaos_active` builds an anonymous object `new { LatencyMs = 0, BrokerDown = false, ServiceFaulty = false }` and asserts on its own literal fields. `ChaosManager` is never instantiated. This is the "Assert.True(true)" anti-pattern in disguise — it will pass forever regardless of what `ChaosManager` does.
- **Fix**: Delete this test and replace with real `ChaosManager` instantiation tests (see HIGH-priority skeleton above). `ChaosManager`'s constructor only needs `IHubContext<LiveConsoleHub>` + `ILogger`, both trivially mockable — no excuse for the stub.

#### MEDIUM: Task.Delay used to "settle" an assertion instead of TestWait.NotHappens
- **File**: `tests/BffWeb/BffWeb.Integration/SignalRPushTests.cs` — `PaymentSessionCreatedEvent_for_a_different_sagaId_does_NOT_land_in_a_clients_subscription`, around `// Allow the consumer to finish processing and any SignalR push to settle. await Task.Delay(2000);`
- **Violation**: This is exactly the "verify absence of a future event" case the shared `BuildingBlocks.Testing.TestWait.NotHappens` helper exists for (per its own doc comment: "the one place a fixed-duration wait is unavoidable... use `NotHappens`"). The test currently does a raw `Task.Delay(2000)` then checks a bool, rather than calling `TestWait.NotHappens`.
- **Fix**:
```csharp
await TestWait.NotHappens(
    () => Task.FromResult(unwantedReceived),
    observationWindow: TimeSpan.FromSeconds(2),
    because: "SignalR group push for a different sagaId must not reach this client");
```

#### LOW: `DemoActivityCounters` has no clock seam, blocking window-expiry unit tests
- **File**: `src/BffWeb/BffWeb.Api/Demo/DemoActivityCounters.cs` — uses `DateTime.UtcNow` directly in `RecordRequest`/`Snapshot`/`Prune`.
- **Violation**: not a rule violation per se, but it's the reason the 15-min session window / 24h request window pruning logic (real branching logic) cannot be unit-tested without `Thread.Sleep`-style hacks.
- **Fix**: Inject `TimeProvider` (or `Func<DateTime>`) so tests can fast-forward, per .NET 8+ convention already likely used elsewhere in BuildingBlocks — flag as a testability improvement, not urgent.

## E2E Coverage Gaps

#### CRITICAL FINDING — E2E checkout tests assert on a SignalR event name/shape that production code never sends
- `tests/E2E/CheckoutE2ETests.cs` and `tests/E2E/CatalogE2ETests.cs` both register:
  ```csharp
  conn.On<string, string>("OnPaymentSessionCreated", (id, url) => tcs.TrySetResult(url));
  ```
  But the actual production consumer, `src/BffWeb/BffWeb.Api/SignalR/PaymentSessionCreatedConsumer.cs`, sends:
  ```csharp
  await hub.Clients.Group(...).SendAsync("CheckoutReady", new { sagaId, orderId, paymentId, checkoutUrl, provider, amount, currency });
  ```
  Two mismatches: (1) method name `"OnPaymentSessionCreated"` vs `"CheckoutReady"`; (2) payload shape — the E2E test expects `On<string, string>` (two positional string args), the consumer sends **one** object argument. If `E2E_ENABLED=1` were ever actually run against real infra, both tests would time out waiting 30s for a push that structurally cannot match, then fail on `tcs.Task.IsCompletedSuccessfully.Should().BeTrue()`.
  - **Impact**: either these E2E tests have never actually run green against the real hub (meaning the "13/13 demos working" status in project memory was never validated by this specific test), or the hub contract changed after the tests were written and nobody updated them.
  - **Fix**: change both E2E tests to `conn.On<CheckoutReadyPayload>("CheckoutReady", msg => tcs.TrySetResult(msg.CheckoutUrl));` matching `SignalRPushTests.cs`'s (correct) integration-test pattern, which already uses the right event name and shape.

- [MISSING] Checkout saga failure path (stock reservation failure, payment failure) end-to-end through BffWeb's SignalR bridge — only the happy path is covered by `CheckoutE2ETests`/`CatalogE2ETests`. `StockReservationFailedSagaBridge` and `PaymentSessionFailedSagaBridge` have no E2E or integration exercise at all.
- [MISSING] Chaos-demo E2E flow (pause a service via `ChaosController`, verify BFF short-circuits to 503 via `ChaosFaultInjectionHandler`, verify auto-resume) — entirely unexercised outside manual portfolio-site clicking.
- [MISSING] Vault rotation SignalR flow (`VaultRotationStageBridge`) — per project memory this demo is "simulated via SignalR" already flagged as fragile; zero automated coverage of the stage-mapping switch that drives it.
- [MISSING] AI service passthrough (`AiController`) — no E2E test exercises BFF→ai-svc for search/chat/recommendations/content-generation, despite `src/Ai` having its own pytest suite; the BFF-side forwarding contract (status code passthrough, SSE streaming for chat) is untested end-to-end.
