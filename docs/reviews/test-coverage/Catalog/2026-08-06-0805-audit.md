- **Type**: Unit
- **Why**: This consumer drives the `Initiated → StockReserved | Abandoned` saga transition. #### MEDIUM: `DemoConcurrencyController` xmin/If-Match concurrency path is untested
- **For**: `src/Catalog/Catalog.Api/Controllers/DemoConcurrencyController.cs:Update`
- **Type**: Integration
- **Why**: This is the platform's live demonstration of optimistic-concurrency (Lens #2). The `If-Match` header priming `db.Entry(product).Property<uint>("xmin").OriginalValue` and the resulting 412 response on a stale write are completely unexercised — if a future EF/Npgsql upgrade silently breaks xmin shadow-property behavior (memory notes this has bitten the platform before — "Npgsql 9 xmin OID bug"), nothing would catch it.
- **Skeleton**:
```csharp
[Fact]
public async Task PUT_inventory_with_stale_IfMatch_returns_412_with_current_state()
{
    var productId = await SeedProductAsync(stock: 10);
    var getResp = await _client.GetFromJsonAsync<JsonElement>($"/demo/inventory/{productId}");
    var originalVersion = getResp.GetProperty("inventory").GetProperty("version").GetString();

    // First writer succeeds and bumps xmin.
    var first = new HttpRequestMessage(HttpMethod.Put, $"/demo/inventory/{productId}")
    { Content = JsonContent.Create(new { quantity = 5 }) };
    first.Headers.Add("If-Match", originalVersion);
    (await _client.SendAsync(first)).StatusCode.Should().Be(HttpStatusCode.OK);

    // Second writer races with the now-stale version.
    var second = new HttpRequestMessage(HttpMethod.Put, $"/demo/inventory/{productId}")
    { Content = JsonContent.Create(new { quantity = 3 }) };
    second.Headers.Add("If-Match", originalVersion);
    var resp = await _client.SendAsync(second);

    resp.StatusCode.Should().Be((HttpStatusCode)412);
    var body = await resp.Content.ReadFromJsonAsync<JsonElement>();
    body.GetProperty("currentInventory").GetProperty("quantity").GetInt32().Should().Be(5);
}
```
